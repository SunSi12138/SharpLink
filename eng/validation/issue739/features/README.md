## Measurement contract

Every cell is a fresh child process. Default is five samples, shuffled with fixed seed and run sequentially; do not run benchmark cells concurrently on one machine. Pin SDK/runtime/source/host. Fixed worker and IO minima 132 across c1/c32. All shapes use the same integer values 0..N-1 and shared precreated source object; one producer enumerator per call is intentionally visible fixture cost. Service async enumerators/consumers, task continuations, assertions and identical completion/item atomics are also included. The original tiny benchmark has a different fixture: supplementary absolute totals are not a drop-in subtraction from it.

`GC.GetTotalAllocatedBytes(precise:true)` measures all managed allocations on every thread in the combined client+server process, including transport and generated stubs. It cannot attribute client versus server or exact objects. Object count remains unavailable without profiler. Gross bytes are not corrected by blindly subtracting fixture controls. Controls still keep live connection + same wire sentinel + tail and report their own results.

Before window: connect/auth/negotiate, allocate payload/producers/listeners/workers/timing arrays, warm up, validate hook activity/real codec activity/context/deadline/token; disable diagnostic hook/telemetry/codec counters, then settle and collect. Pass-through hooks remain enabled; their body is a flag branch plus `next(context)`. The allocating plugin remains allocating. Authentication/deadline/context assertions are activation-only. Every service uses the same atomic call/item observation in measured work, so totals are fixture-inclusive.

Warmup and measurement both use fixed expected service completion counts, not moving snapshots. After workload, a same-connection wire sentinel, expected receiver/service completion count and zero `ActiveCallCount` are awaited; a fixed 20ms tail is included, then counts/inactivity are checked. This is bounded quiescence observation, NOT a formal proof that every AsyncLocal/receive-loop/transport cleanup finished. Final stop/disposal is outside measured window. Tail allocations remain in gross result and must be considered using controls/amortization.

For successful calls report B/call, input items received at server, output items produced at server and consumed at client, B/input-item, B/output-item, and B/total-items. Duplex has 2N total items per call; label denominator explicitly. OneWay client latency is send completion; final receive/drain/tail is in aggregate totals. Per-call latency, workload duration and tail/drain duration are separate. Tail-inclusive total duration is not pure transport throughput. Validate exact call/item counts and sums/order; a missing or failed cell is never a zero.

Three stream lengths permit a descriptive startup/slope fit of B/call versus N, but show residuals and raw points; don't assume linearity across pooling/batching thresholds. Compute deltas only between same transport/concurrency/mode/payload/producer/control. Publish sample medians and spread; fewer than five or tiny-operation smoke samples are only pilots, not stable allocation claims.

## Execution

Build `Features.csproj -c Release -m:1 -p:UseSharedCompilation=false`. Arguments: transport mode concurrency calls warmup sample output feature items producer control.

Use `run_matrix.py --dotnet <path> --dll <Release/net10.0/SharpLink.Benchmarks.dll> --output <dir> --stage streams|features|spotchecks|suspension --samples 5`. Run stages separately; long runs only after review. `--pilot --samples 1 --transport tcp` is explicitly smoke. Main author owns workflow integration and publication. This worker does not commit, push or dispatch CI.

The runner fails closed on a missing/malformed JSON, wrong source/shape/count, nonfinite/negative byte or latency field, inconsistent B/call, or reused PID+process-start identity. It records assembly SHA256, harness source hashes, runtime-related environment, and per-cell median/min/max/CV for B/call and p50/p99. Five unique processes are a minimum only; review variability and host comparability before any stability claim. A subprocess timeout is saved as failure, not a successful/missing-zero sample.

## Separate receive-bounded OneWay revision (v2)

The historical main f2662966 hosted `shm-oneway-stream c32 N1` send-completion-policy warmup failed with `ResourceExhausted: The session is already waiting for completed stream capacity to be released.` Preserve that raw failure and original partial results. The original policy limits simultaneous sends, not receiver-completed logical calls; it can accumulate a much larger receiver backlog. Runtime send-state/tombstone capacity is bounded, and at most one pending send-state-capacity waiter is allowed (`StreamFlowController.cs`). This is evidence of that offered-load boundary, not a successful allocation measurement or proof of a production leak.

An explicit final argument `receive-bounded` selects a NEW OneWay workload; omitting it retains `send-completion` for OneWay (`not-applicable` for other modes). The bounded RPC uses a separate, otherwise identical OneWay input-stream method so the old service method is unchanged. It uses a precreated SemaphoreSlim(c,c) and acquires one receiver credit before sending. The service releases exactly once, in finally, only after successfully consuming the full input stream and incrementing the successful-completion counter. Send/service errors cancel all pending gate waits and invalidate the sample. No response/Task acknowledgment is added to the wire protocol.

The same limiter and observers run for matched direct fixture controls. Gross managed allocations include semaphore waiters, cancellation registrations and scheduling; their cost may differ between RPC and direct controls, so do NOT blindly subtract them. Report acquired/released counts, peak receiver-outstanding, final credits, pending-wait observations and aggregate acquire-wait time (including uncontended acquire cost). Validate acquired=released=completed=calls, final credits=c, outstanding=0 and peak<=c. A pending-wait observation means WaitAsync was incomplete when inspected; it does not prove the await suspended. Acquire time is summed across concurrent workers, so do not add it to wall time or send percentiles. Gate acquisition happens before the send-latency clock: send latency and credit wait are separate; whole-window allocation/time includes both. Credit release is NOT a protocol stream/tombstone cleanup fence. If this bounded fixture also fails, report the workload limitation; do not change runtime limits or conceal the failure.

To run only the bounded replacement OneWay matrix: `run_matrix.py --dotnet <path> --dll <dll> --output <new-dir> --stage streams --only-mode oneway-stream --oneway-load-policy receive-bounded --samples 5`. This selects 24 cells: both transports × c1/c32 × N1/16/256 × rpc/fixture, each five fresh-process samples. Use a new output directory. It does not overwrite, relabel, complete, or repair the original failed matrix. Original valid cells and v2 cells remain separate source/fixture revisions.
