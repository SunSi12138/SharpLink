## 需要明确裁决的边界

| 边界 | 提案与决定依据 |
|---|---|
| RuntimeContext / Builder | 保留 standalone serialization SPI：无需启动 Client/Server 就能解析 owner-manifest codec、验证 golden bytes 与 Decode；创建者 Dispose。已退役的 `AddCodec`、`UseCodecResolver` 不恢复。 |
| API5 generated ABI | 保留跨用户生成程序集所需的窄接口、factory/descriptor/manifest 和 wire/sizing ABI。`EditorBrowsable(Never)` 不改变可见性；公开不等于业务代码可接管 Session。 |
| ProtocolV2 | 15 个类型共 **244 个声明 ID（15 类型 + 229 成员）**保留。它们是 Accepted ADR0001 的协议数据、解析和编码 SPI，不是 live Session mutator。 |
| 内建 transport concrete | 八个类型全部维持 public sealed。逐个构造能力和高层入口差异见[审核记录 B5](3.0-api-surface-audit-decisions.md#八个内建传输类型)；不把 Socket accepted-socket options 写成“接纳既有 Socket”。 |
| 三个 `CloneValidated` | `BufferWriterPoolOptions`、`RuntimeConcurrencyOptions`、`SharpLinkProtocolOptions` 的方法返回**经过验证的独立可变副本**，属性 setter 仍可使用；保留 standalone 配置用途，不称 immutable snapshot。 |
| 两个 Catalog `CreateSnapshot` | 保留 legacy inspection：枚举当前仍存活的弱目录条目。owner-scoped 注册/解析没有等价的全量无损枚举接口；返回的强引用列表会在调用者持有期间保留 manifest。 |
| `RpcGeneratedCodecSizing` | 保留实际 2.0.3 已发布的同线程 `IsSuppressed/Enter/Exit` helper；不把它称作当前 Generator 的必需依赖，也不新增跨 async scope 承诺。 |
| `RpcGeneratedCodecResolver` | 保留 Assembly/Type owner-codec 桥接；registration-bound overload 继续 internal，当前 Generator 不调用 Runtime helper。 |
| 内部 `StreamTransportConnection` | `TlsStreamTransportConnection` 真实直接继承，不能 sealed。其余内部基类同样记录 `base` 边，不用 `base-type-dependency`、泛型参数或外层容器依赖冒充派生。 |

公开继承保留：`SharpLinkCallContextSnapshot` → `SharpLinkServerInvocationContext`；
`SharpLinkAdmissionRuleOptions` → `SharpLinkPartitionAdmissionOptions`；`SharpLinkException` 的库内派生和外部异常扩展；
`SharpLinkTransportAddress` 的内建地址和自定义 endpoint factory 地址扩展。

本次重新从官方 NuGet 下载 **2.0.3 Abstractions/Runtime** 包，用既有 `SharpLink.PublicApi` 提取器检查：
15 个 ProtocolV2 类型区段与当前 `eng/public-api/3.0.0` reviewed snapshot **逐字相同**；
三个 options、两个 Catalog、legacy Sizing 的六个完整区段也相同。
[证据记录](evidence/api-ledger-protocol-and-helpers-2.0.3.json) 包含来源、nuspec repository commit、DLL 身份和逐类型结果。
当前一端是仓库 reviewed snapshot；最终拟发布包仍须重新提取并与它比较，不能把此结果当作最终 nupkg 签审。

## 复核覆盖，不自动批准

在 artifact 仍可下载时：

```bash
gh run download 39986953281 -n api-inventory-39986953281-1 \
  -D artifacts/api-ledger-source
python3 eng/verify-api-decision-ledger.py \
  artifacts/api-ledger-source/api-inventory/pr
python3 -m unittest discover -s eng/tests -p 'test_api_decision_ledger.py' -v
```

PR Fast 运行离线正负对照；它们不重新运行已通过的 Roslyn fixture。

校验器从全部 `symbols.jsonl` 独立推导 `externallyVisible || nonSealedClass` 集合，核对原始
`needs-decision` 清单、完整的 10 个 target、逐目标计数、类型和每个展开后的 ID。
成员 ID 使用 `M:`/`P:`/`F:`/`E:` 加类型内后缀；以 `=` 开头的项保留完整 DocID，适用于 Roslyn C# 14 extension 容器。
每个类型的 `memberDecision` 只应用于锁定的精确成员列表；nested 类型单独有条目，accessor 和 compiler-implicit 成员不丢弃。

缺失、额外、重复、放错容器的 ID，以及遗漏的成员例外说明、无效依据、错误继承边或不完整 target 均失败。
新增成员不会被一个宽泛类型规则静默接纳。校验绑定输入的 commit/tree、运行配置和 SDK；
本提案的 `inventory.sdkVersion` 为实际库存中的 `10.0.113`，每个 actual target 都必须精确匹配，缺失或混用 SDK 均失败。
新的来源必须重新分类和绑定；
它不修改原始库存，也不把 `proposal-not-approved` 转换为 approved。

这是一份固定输入的决策提案，不是针对任意当前工作树的签名兼容性门禁。最终 HEAD 的签名、包、forwarder 和跨平台行为
仍由既有 Release Gate 检查；同一 ID 的签名变化必须在新库存与实包 diff 中重新审阅。
