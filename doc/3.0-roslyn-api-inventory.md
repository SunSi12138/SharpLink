# 生产程序集 Roslyn 声明库存（#805 部分交付）

此工具产出当前主机、Release 配置下的**生产声明与签名关系证据**，不自动批准 `internal`/`sealed` 修改，也不以零引用或未发现派生类作为删除依据。它没有完成 #805 的全部符号分类、消费者覆盖和最终 Release Gate。

## 执行与覆盖

```bash
python3 eng/run-api-inventory.py --output artifacts/api-inventory/candidate
```

输出目录必须不存在。工具使用仓库 `global.json` 选择的 SDK 和当前配置的 NuGet 源；需要 Python 3.10+、.NET SDK，以及首次恢复工具依赖所需的访问能力。它会编译自己的非 shipping `eng/SharpLink.ApiInventory`，随后处理 `eng/api-inventory/scope.json` 声明的范围。

- 自动发现 **全部 `src/**/*.csproj`**；不是硬编码九个程序集。新增 GenerationControl 或其他生产项目会进入发现清单。没有项目文件的 `SharpLink.Shared` 由实际链接它的编译项目记录，不虚构一个程序集。
- 通过 `dotnet msbuild -getProperty/-getItem` 评估项目和全部 `TargetFrameworks`，保留每个 target 的程序集名、包属性、常量、语言版本、Compile/ProjectReference/AdditionalFiles 选择和文件哈希。
- 正常构建项目及引用，再强制重新编译当前目标并导出真实 compiler-generated 文件。生成器加载/初始化/执行失败的 `CS8032/CS8033/CS8034/CS8784/CS8785` 不能作为可忽略警告通过。
- 用 SDK 自带的 MSBuild 和 Roslyn 5.0 workspace 打开实际项目；不把目标 TFM 作为 workspace 全局属性传播到引用项目。按 MSBuild 实际 `TargetPath` 精确选择对应 inner target，拒绝缺失或歧义选择。
- 使用已构建的引用程序集；若 workspace 退回加载引用项目源码，或出现 workspace/analyzer/compilation 错误，报告标为不完整。
- 合并普通 `Documents` 与 `GetSourceGeneratedDocumentsAsync()`，检查它们与最终 compilation 的语法树一一对应。生成文档的 assembly/type/hint 路径必须和真实 compiler 输出逐份对应，默认要求文本哈希一致；仅允许下述经过限定检查的 Logger namespace 块换序，所有原文和不一致哈希仍保留。生产配置要求 Client 和 GenerationControl 的实际生成文档存在。

每个项目失败均留在 coverage 和日志中，并返回非零；不会静默略过失败项目。失败报告中可能保留已成功提取的部分符号，不能把其计数当作完整总数。每次运行都保留 source/tool Git commit、tree、dirty 状态、控制文件/工具文件/程序集/报告哈希。最终发布应在干净拟发布 HEAD 上复跑；dirty 运行只是绑定了当时输入的工作证据。

## 输出和计数口径

| 文件 | 内容 |
|---|---|
| `coverage.json` | 已发现的项目×TFM、每个目标是否完成、各 origin/accessibility 的计数、type 的 sealed/abstract 分组、未覆盖范围、失败原因。 |
| `targets/*/evaluation.json` | 实际 MSBuild 评估结果和 Compile/ProjectReference/AdditionalFiles 哈希。 |
| `targets/*/target.json` | compilation/parse options、所有文档、additional files/analyzer configs、metadata references、生成器程序集身份/MVID/hash、编译诊断。 |
| `targets/*/build-generated/`、`workspace-generated/` 和日志 | compiler 与 workspace 两份实际生成原文，以及项目构建、强制编译、workspace 执行的原始诊断。Roslyn Project 的公开 API 不暴露 GeneratorDriver diagnostics，因此生成器失败门禁来自真实 compiler 构建，生成声明再由 workspace 逐份核对。 |
| `symbols.jsonl` | 类型及成员语义记录；稳定 ID 包含项目、TFM、程序集简单名和 documentation-comment ID。无 DocID 的符号使用包含 metadata name、kind、完整显示签名的 fallback；重复 ID/未知成员或签名类型直接失败。 |
| `relations.jsonl` | 直接 base/interface（不把泛型参数或外层类型当作继承）、独立的 base/interface-type-dependency、签名类型（包括泛型参数、数组、指针、function pointer）、attribute type 参数、override、显式接口实现、IVT 关系。目标引用用程序集简单名+DocID，实际引用程序集字节另有哈希；这不是方法体调用图。 |
| `decisions.json` | 所有外部可见声明和 non-sealed class 的显式 `needs-decision` 清单；没有自动批准、默认“安全删除”或覆盖人工台账的模式。 |
| `inventory.md` | 每目标结果与所有 non-sealed class（包括 abstract/internal）的索引。 |
| `provenance.json` | source/tool 来源、SDK/运行环境的相关证据、输入/工具/输出 SHA-256。 |

声明遍历从 `Compilation.Assembly.GlobalNamespace` 出发，递归 named/nested 类型以及类型成员；包括接口、record、delegate、enum、构造/方法/操作符、属性/indexer、accessor、字段和事件。C# 14 extension 声明、显式接口实现、参数 ref/scoped/nullable/default、泛型约束、required/init 等保留在签名或结构化字段中。partial 声明合并，所有声明及源码位置保留。编译器隐式成员不会被过滤。

文档、声明及位置的内容哈希基于 Roslyn 读取文本的 UTF-8 表示（不含 BOM）；程序集、控制文件和工具文件的哈希基于原始文件字节。工具沿用仓库的 [Roslyn workspace 5.0.0](https://www.nuget.org/packages/Microsoft.CodeAnalysis.Workspaces.MSBuild/5.0.0)，CSharp 依赖在工具内对齐 5.0.0；新增的 [Microsoft.Build.Locator 1.11.2](https://www.nuget.org/packages/Microsoft.Build.Locator/1.11.2) 只用于加载所选 SDK，不进入 shipping 包。

计数分成 `explicit-source`、`source-generated` 和 `compiler-implicit`，最后一类优先；`hasGeneratedSource` 独立保留隐式生成来源。普通文档包括 MSBuild 生成后作为 Compile 输入的文件，因此 explicit-source 不等同于“人工编写”。属性的 accessor 是独立 method 行并关联 property/event，不冒充额外属性。按 TFM 的行数与去掉 TFM 的 union identity 数分开；相同 DocID 不代表不同 TFM 的签名完全等价。

`declaredAccessibility` 与容器约束相交后的 `effectiveAccessibility` 分开记录。例如 internal 容器中的 public nested 类型有效范围为 internal。嵌套 protected 的可达性还受具体继承关系限制，因此同时保留完整 containing constraints；`externallyVisible` 是可见范围上界，不能证明某个外部调用者必然能访问。IVT 授权是单独 assembly relation，不冒充 public API。

## 独立的人工决策台账

[3.0 紧凑台账](3.0-api-decision-ledger.md)基于 #943 成功 hosted 库存逐类型提出保留理由，单列成员例外，并以独立校验器检查精确 ID 覆盖。状态为 `proposal-not-approved`；原始 `decisions.json` 仍保持 `needs-decision`。它绑定固定源码/运行配置，不自动接纳未来新增声明，也不代替最终 HEAD 和实包签审。

## 工具验证

```bash
python3 -m unittest discover -s eng/tests -p 'test_api_inventory.py' -v
```

真实的小 fixture 有两个 consumer TFM、一个不同 TFM 的 generator、跨程序集基类、链接源码和真实 incremental generator。验证覆盖 nested/internal/protected/private-protected、partial record 和 implicit/accessor、显式接口、泛型 arity、C# 14 extension、function pointer、生成 internal/nested 声明以及条件编译成员。

负对照包含缺失/重复/失败/意外 target，以及故意让 generator 抛异常：后者必须返回非零、标记两个 consumer 失败，并保留 `CS8785` 日志。确定性 synthetic generator 的同输入重复运行要求 symbols、relations、coverage、decisions 及每目标报告逐字节一致。真实 Logger probe 会生成带 EditorBrowsableAttribute 的七参数日志 struct，独立构造 namespace 排列、正文/成员换序、重复 partial 类型、header、禁止属性/指令、错误 generator/hint 的正负对照，并按保存的 workspace 原文检查每个声明 span/hash。fixture 的报告标记为 `synthetic-fixture`，不混入生产统计。

独立 [API Inventory 工作流](../.github/workflows/api-inventory.yml) 在相关 PR 和手动触发时，先运行这些 fixtures，再运行真实生产库存；它只调用工具与逐项目构建，不重复编译整个 solution。`Roslyn API inventory` hosted job 必须通过后才可将此工具 PR 合并，不能用 PR Fast/CodeQL 的通过替代。工作流始终尝试上传原始成功/失败证据（`api-inventory-<run_id>-<attempt>`，30 天），不会自动修改 needs-decision 分类。

Release Gate 的 pack 作业仍在最终集成构建后重新运行相同验证和生产库存，上传 `roslyn-api-inventory` artifact（30 天），包括失败日志。

## LoggerMessage namespace 顺序的受限比较

已发布 Microsoft.Extensions.Logging.Abstractions 10.0.12 的[生成器实现](https://github.com/dotnet/dotnet/blob/95017c711e6afc1085133d440e42b4bd78155701/src/runtime/src/libraries/Microsoft.Extensions.Logging.Abstractions/gen/LoggerMessageGenerator.Roslyn4.0.cs) 对 syntax class 使用 `ToImmutableHashSet()`，随后按该枚举顺序输出类型；独立 compiler/workspace 进程可能交换完整 namespace 块的次序。这不是丢失或改写生成代码的许可。

唯一例外限定于实际加载的 `Microsoft.Extensions.Logging.Generators.LoggerMessageGenerator` 的 `LoggerMessage.g.cs`。工具核对 analyzer 文件和已加载 generator 类型的 assembly identity、MVID、SHA-256，要求 logical path、generator type、hint 全部一致。只有下面条件全部满足才记录 `matchKind=logger-independent-namespace-order`：

- 两端均可解析；没有顶层 using/extern/global attribute/statement，每个 block namespace 只有一个 partial class。
- 按规范化 namespace、class identifier 和 arity 得到的类型身份各不相同；同类型 partial 块不会获准换序。
- 仅有相同、固定、位于开头的 `#nullable enable`；禁止 pragma 和其他/块内 directive。
- 只允许绑定生成器身份/version 的完整 `global::System.CodeDom.Compiler.GeneratedCodeAttribute`，以及精确的 `global::System.ComponentModel.EditorBrowsableAttribute(global::System.ComponentModel.EditorBrowsableState.Never)`；ModuleInitializer、属性别名和其余属性全部拒绝。
- 每个 namespace **完整原始 span** 的内容必须相同，header/footer/块间分隔符也必须逐字相同；分隔符/footer 只能是空白。因此正文、成员顺序、属性、字面量、增删声明都不会被忽略。

`target.json.generatedComparisons` 保留两端 hash、文件路径、generator binding、类型排列与拒绝原因。两份源码都不做 canonicalize 或重写。`DocumentEvidence.snapshotPath` 指向保存的 **workspace** 文本；库存声明/位置的行号和 UTF-16 span 都来自该 workspace tree，其 span 内容哈希由对应范围计算，不借用 compiler 另一排列的偏移。

必须区分稳定的 declaration identity/signature/片段内容与本次排列的全文 hash、行号、offset、provenance。上游排列变动时，后者可以变化；不承诺含这些原始位置的生产报告逐字节稳定。受限比较只证明本轮声明覆盖等价，不是运行时行为兼容性或人工 API 决策批准。其余生成器或任何未满足上述条件的差异仍返回失败。

## 明确未覆盖，不能据此关闭 #805

- 当前 CI 运行主机之外的 OS/RID 条件组合；即使 TFM 相同也不推断跨平台等价。
- demo/test/samples 的全部 generated consumer、PackageSmoke/SDK-only/Abstractions-only、AOT/ALC/DI/反射及 Generator.Tests 字符串输入。此切片只做 production-declarations，fixture 只是工具自身验证。
- 方法体 invocation/member-reference 调用图、反射字符串、动态加载、外部继承者和用户代码。局部变量、局部函数、lambda，以及仅在 metadata lowering 后出现的 async state-machine 等不是此类型/成员声明库存。
- 原始源码语义库存与实际 nupkg public/protected/forwarder 的逐条映射，以及全部 attribute 细节。人工台账另有精确覆盖校验，但独立审批与最终 HEAD 变更审核仍待完成。实包差异仍由独立 public API 工具提供。
- 最终候选 HEAD 上的逐项分类、breaking change 审批、迁移说明核对和所有平台 Release Gate。
