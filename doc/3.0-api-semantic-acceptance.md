**Decision: accept the exact reviewed source API surface.** This is a source-governance decision, not package, runtime, performance, merge or release approval.

The [acceptance manifest](../eng/api-inventory/3.0-semantic-acceptance.json) binds the fixed `3d76a3a8b55a37e24c62a073fe588cff3d3867be` ledger files by SHA256. Their 302 type owners / 3397 exact required IDs were independently reviewed in 14 roles against current code and fixed member sets. All 11 actual-inheritance decisions and 5 member exceptions are accepted. The original proposal files and validator remain unchanged: this separate acceptance records the completed review rather than rewriting historical evidence.

All 109 additions and 12 changes are enumerated in the manifest with reasons. There are no required-ID removals; 3385 records are unchanged. The current accepted set is exactly 311 types / 3506 required IDs, including compiler/accessor members. Equality alone was not approval; review covered purpose, ownership, accessibility, signatures, nullability, defaults, attributes, base/interface shape and authorization boundaries. No future-member wildcard or additional API narrowing is accepted.

## Scope decisions

- Preserve useful public contracts, extension/codec/transport/provider SPI, generated ABI, configuration and diagnostics; preserve real inheritance without promoting internal types.
- Preserve two caller-owned strong snapshots over weak catalogs and three independently mutable `CloneValidated` copies. Neither is an immutable lease or authorization receipt.
- The nine new maintenance types and two enum values are restricted to [#933](https://github.com/SunSi12138/SharpLink/pull/933): host authority, fixed authenticated built-in TLS cohort, compatible server implementation replacement, sealed configuration, full physical quiescence and fail-closed behavior. They do **not** accept full [#775](https://github.com/SunSi12138/SharpLink/issues/775), remote assembly loading, incompatible client/contract upgrades or ordinary per-RPC management lookup. Public results cannot forge internal proof; observer cancellation is not physical drainage.
- `ISharpLinkClient` / `ISharpLinkServer` gain no mandatory members. Eleven changed type records have only incident-relation changes; one internal stream base gains two internal quiescence interfaces. Existing public transport SPI is not widened.
- Correctness-first 3.x breaking migration is permitted: matching generated ABI consumers must regenerate/rebuild. No 2.0.3 binary compatibility promise is made.
- Clarification: `SharpLinkAuthenticator.CreateClient` and `CreateServer` each allocate a private sealed adapter. The accepted rationale is narrow callback forwarding, **not allocation-free construction**; no API change is required.
