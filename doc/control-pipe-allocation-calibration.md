# Public control-pipe allocation calibration (#387)

The previous fixed path-count run ([37929963664](https://github.com/SunSi12138/SharpLink/actions/runs/37929963664)) explains current c1 allocation variation through incomplete control-pipe reads. It does not reproduce the historical gate failure. The high sample had 600 more incomplete calls but only 134 more total calls, demonstrating a changed completion mix. Individual calls are not paired across those samples.

This final bounded calibration uses official public `PipeStream` APIs and connected one-byte NamedPipe streams. Both overloads use `CancellationToken.None`, matching production. It compares the Memory/ValueTask and byte-array/Task overloads with the same buffers, payloads, 512-operation warmup, and five fixed 4000-operation mixes: 0%, 25%, 50%, 75%, and 100% pending reads. Within each 100-operation block, the pending calls come first. No repeated or selected sample is accepted.

Ready calls follow a completed write and must immediately return a successful read. Pending calls start on a drained pipe, must return incomplete before the write, then consume the original result once. Every byte is checked. The predicted call-boundary cost on the pinned Linux .NET 10.0.12 runtime is 0 versus 144 bytes. Independent synchronous current-thread counters must agree exactly with the disjoint observer counters. Valid measurements that refute the 0/144-byte hypothesis are retained and reported as such; the alternative overload is not forced to have the same cost. Primitive observer thread state is primed before each raw call boundary; first touches remain exposed, with initialization and orchestration allocation in the signed process residual. Snapshots and every completed sample are retained; failure stops the sequence and preserves partial evidence.

A setup-only deadline registration disposes the reader after 60 seconds, bounding otherwise uncancellable measured reads. Cancellation/reuse and pending-read disposal are checked separately for both overloads on fresh pipe pairs, outside measured populations. These checks do not change the runtime implementation or transport protocol. Normal builds exclude the diagnostic CLI and helper.

The measured unit is B/read. It must not be treated as RPC B/op or as sufficient evidence of an RPC budget failure; this is explicitly not a gate failure reproduction. The array overload comparison tests a safe API alternative; equal costs provide no repair. No removal of waiter-arm recovery, in-flight notification suppression, socket internals, budget change, or further gate repetition is proposed here. If neither public overload removes the cost, the result is a documented limit requiring a separate decision about larger runtime work or gate-policy design.
