## 明确的边界原则

1. **只有真正的用户 API、配置模型、可实现的扩展 SPI 和版本化 Generated API 5** 应保留 public；`EditorBrowsable(Never)` 不是访问控制。Generator 输出必须继续跨程序集编译。
2. **尚无派生类**不是添加 `sealed` 或删除 `public` 的充分条件。检查库内继承、用户继承、DI、Hosting、ALC、Source Generator、AOT、Trim 和实际已发布 NuGet API。
3. **新增 public→internal、移除成员与 sealed 均可能是 breaking change**：每条拆成最小 PR，对 `eng/public-api/3.0.0/*.api.txt` 做定向审阅。3.0 不承诺兼容 2.x，但必须记录迁移。
4. **固定测试套件规模**的专项门禁会检查 UnitTests 计数；将边界断言纳入既有案例，不降低计数门禁阈值。
5. 同一 `dev` 合并多条 PR 后必须重新跑最新 HEAD 的 Release Gate；单条 PR 的绿色 CI 不等于最终的版本化签审。

## 留在 public 或可继承边界的明确反例

- `IClientTransportFactory`、`IServerTransportListener`、`ITransportConnection`、`IRpcCodec<T>`、Adapter/Codec factory、interceptor、authenticator、selector、retry 等：**真实外部可实现 SPI**，继续 public。
- `IRpcRuntimeContext`、`IRpcContractCodecProviderResolver`、`IRpcChannel`、Generated codec/contract manifest/descriptor、`IRpcStub` 和 `IRpcGeneratedServerBridge`：**版本化生成代码 ABI**，即便用户业务不应直接操作也不能因“仅框架使用”而 internal。
- `SharpLinkCallContextSnapshot` → `SharpLinkServerInvocationContext`、`SharpLinkAdmissionRuleOptions` → `SharpLinkPartitionAdmissionOptions` 与 `SharpLinkException` 的派生关系：不能盲目 sealed。
- 直接可供用户配置的 Client/Server/MultiCluster Fluent 入口、公开诊断快照、Metadata、Hosting/DI：维持表意清晰的 public 成员。

## B4/B5 逐项保留依据（2026-10-23）

本轮按 `751ecd34ec29bc51062e356d378d9a0792a90171` 核查以下边界，决定保留现有 API；没有新增公开入口、IVT 或继承能力。此处的 **keep** 是契约决定，不等于全仓符号盘点或最终发布门禁已完成。

### Codec helper 的三种不同用途

| 边界 | 当前证据与决定 |
|---|---|
| `RpcGeneratedCodecResolver.GetProvider(IRpcRuntimeContext, Assembly)` | 保留公开的 owner-assembly 桥接，转发到可由外部实现的 `IRpcContractCodecProviderResolver`。Type overload 向它汇聚；不能因 Client/Server 有 IVT 就宣称跨程序集调用本身足以要求 public。 |
| `GetProvider(IRpcRuntimeContext, Type)` | 保留已发布 compatibility overload。ClientAssemblyRegistry、Server Builder 和动态注册路径仍有真实调用；Type 只映射到所属 Assembly，不形成另一个 owner policy。当前 Generator 不引用这个 Runtime helper。 |
| registration-bound `GetProvider` overload | 保持 internal；它关联 Runtime 的注册所有权和缓存，不扩大成外部 API。 |
| `RpcGeneratedCodecSizing.IsSuppressed/Enter/Exit` | 保留已发布的 legacy public helper，不把它称作当前生成代码必需。实际 2.0.3 Abstractions 包已有这三个成员；当前 Generator、生产调用与 package consumer 源码没有使用它。无当前仓库调用不能证明外部直接消费者不存在，本轮不另加删除或 internal 化的 breaking change。 |
| `IRpcSizedCodec<T>` / `IRpcSizedCodecSnapshot` | 当前 generated sizing/snapshot ABI，继续 public。Generator 实际输出 `TryGetEncodedSize`、`SerializeSized`、`ReleaseSnapshot` 及子 snapshot 所有权处理，与上述 legacy Sizing 类不是同一件事。 |
| `RpcGeneratedCodecWire` / `RpcGeneratedWireType` / `RpcGeneratedLengthToken` | 当前 generated wire ABI，继续 public；Generator 输出 presence/field-key/length 边界操作。LengthToken 是公开 helper 的返回/参数类型，隐藏构造也无法阻止 default/init/with，不为此另加 breaking。 |

Sizing 的历史判断不是从二进制字符串推断的：2.0.3 SDK analyzer 虽含该名字，对应源码调用位于未被调用的 `AppendDtoExactSerializeBody`；[#810](https://github.com/SunSi12138/SharpLink/pull/810) 删除了这个死 emitter。已检查的 API3/API4 冻结 fixture 也没有该类型名，这仍不代表全部外部消费者。实际 2.0.3 Abstractions 包 SHA-256 为 `596e40b616e619a83303d108e66ebe3828d16be720e95dfc061ca76027517464`，发布提交为 `4f9295ffb37ce68985051c11bfd9afc0e23166f3`。`EditorBrowsable(Never)` 不撤销其 public 可访问性；保留不改变现有线程静态 Enter/Exit 语义，也不新增跨 async scope 的承诺。

### 八个内建传输类型

这些类型定义在 `src/SharpLink.Runtime/Transport/`。接口 SPI 允许外部实现，内建 concrete 通过组合或包装使用；它们均已 sealed，不需要再次封闭继承。

| 类型 | 直接构造的能力与保留理由 |
|---|---|
| `SocketClientTransportFactory` | 接受 EndPoint、完整 SocketTransportOptions 和 TLS/timeout。固定 UseTcp 不暴露 socket options；topology 工厂虽有相应配置，仍保留独立 IClientTransportFactory 组合入口。 |
| `SocketServerTransportListener` | 接受 bind EndPoint、backlog、accepted-socket NoDelay/keepalive/buffer options、TLS/timeout，并提供 LocalEndPoint。Server UseTcp/UseUds 不暴露 SocketTransportOptions；没有发现接纳外部既有 Socket 的公开构造。 |
| `NamedPipeClientTransportFactory` | 接受 serverName 与原生 PipeOptions；高层 AllowCrossUserAccess 配置不等价于 WriteThrough 等原生选项组合。 |
| `NamedPipeServerTransportListener` | 接受 maxServerInstances、PipeTransmissionMode、原生 PipeOptions；高层 UseNamedPipe 没有完整等价参数。公开配置仍受各平台本身支持范围限制。 |
| `AnonymousPipeClientTransportFactory` | 继承 handle 字符串的 one-shot factory。高层已有便捷入口，保留已发布的独立组合能力；SafePipeHandle 构造保持 internal，同进程 offer 的安全所有权路径不变。 |
| `AnonymousPipeServerTransportListener` | 提供 offerQueueCapacity，并实现 IAnonymousPipeAllocator；高层 UseAnonymousPipe 只有默认容量，不能通过隐藏 concrete 删除可配置的有界队列能力。 |
| `SharedMemoryClientTransportFactory` | 接受 SharedMemoryTransportOptions；高层已有等价 options，保留直接 factory 的组合及传输层使用能力，不虚称高层缺参。 |
| `SharedMemoryServerTransportListener` | 高层已有等价 options，保留独立 listener 的组合、Accept/Dispose 使用能力；公开类型不扩大共享内存的平台支持承诺。 |

`SocketTransportOptions`、`NamedPipeTransportOptions`、`SharedMemoryTransportOptions` 是公开签名中的用户配置 DTO，维持 public sealed；其内部复制/转换实现不公开。`AnonymousPipeOffer`/`IAnonymousPipeAllocator` 是子进程或安全同进程连接的所有权入口，继续公开。`RpcSessionFlushOptions` 保持 public readonly record struct，单隐藏主构造不足以阻止 default/init/with。

继承保留有明确用途：`SharpLinkCallContextSnapshot` 和 `SharpLinkAdmissionRuleOptions` 各有框架派生类；`SharpLinkException` 是异常扩展边界；`SharpLinkTransportAddress` 的 abstract record 允许自定义 endpoint factory 解释派生地址。内建 factory 对不认识的地址拒绝处理，不代表禁止外部扩展。保留自定义异常不承诺在远端重建任意 CLR 异常子类。

已有 PackageSmoke 的非友元实包消费者实现 transport/codec/authenticator/resolver/selector/retry/admission/interceptor 等 SPI，并验证适用 SPI 的 Builder 配置；codec/connection 验证的是可实现性，不代表恢复动态 Codec 注册。新增的 [`ExternalApiBoundaryProbe`](../test/SharpLink.PackageSmoke/ExternalApiBoundaryProbe.cs) 补充这些具体边界：`CompileTransportConstructors` 编译八个内建 concrete 的公开构造及配置参数，但从不调用该方法，避免创建 listener/socket/pipe；其余运行断言覆盖 Resolver 的 Assembly/Type 同 owner 转发、不同 owner 的隔离与 null/unsupported 错误，legacy Sizing 的同线程嵌套平衡，以及外部 exception/address 的本地继承和值语义。该文件由 PackageSmoke 的 SDK Compile glob 纳入，`Main` 只调用纯逻辑断言，CI 继续使用既有实包和 fresh-cache 流程。它不证明八种传输配置在所有平台都能运行、不恢复动态 Codec 注册、不承诺跨 async 的 Sizing scope 或远端 CLR 异常子类重建；最终 generated ABI/ALC/Trim/AOT 与各平台发布矩阵仍需验收。
