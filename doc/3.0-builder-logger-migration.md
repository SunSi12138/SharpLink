# SharpLink 3.0 builder logger configuration

`UseLoggerFactoryIfUnset(ILoggerFactory)` is a **Hosting-only fallback injection hook**, not an application configuration policy. In 3.0 this method becomes `internal` on `SharpClientBuilder`, `SharpLinkServerBuilder` and `SharpLinkMultiClusterClientBuilder`. SharpLink.Hosting retains access through explicit internal assembly friendship.

Applications should choose their logger through the supported public Fluent methods:

```csharp
clientBuilder.UseLoggerFactory(appLoggerFactory);
serverBuilder.UseLoggerFactory(appLoggerFactory);
multiClusterBuilder.UseLoggerFactory(appLoggerFactory);
```

For a multi-cluster coordinator, the effective priority is **explicit child > explicit coordinator > Host default**. An explicit child logger is configured in its `AddCluster` callback. Coordinator logger inheritance is applied before the child Build freezes the plan, so it does not matter whether `UseLoggerFactory` is called before or after `AddCluster`. Hosting installs only a fallback and must never override an explicitly configured logger.

Runtime Add/Replace child clients inherit the frozen coordinator logger unless they set their own. Logger factories are application-owned and are not disposed by the builders. This is an intentional 3.0 public API cleanup; do not backport it to 2.x.
