# ADR 0001: 2.0 public API 与包边界

Status: Accepted
Date: 2026-09-13
Tracking: #86 / #67

## Context

2.0 在已发布 1.1.1 之后提供一次 source/generated ABI 破坏性升级。生命周期重构已将
Session、StreamManager、dispatcher、构建 transaction、manifest publication 与 counter owner
收进内部实现。本轮必须固定可支持的公开边界，避免用包拆分代替所有权设计。

## Decision

| Surface | 分类与保留理由 | 所有权/使用边界 |
| --- | --- | --- |
| Client、Server、Hosting、metadata、readiness、health、support snapshot、control-plane result | 业务调用、配置与诊断 | 应用创建 owner；等待 Stop/Dispose 和 mutation cleanup；snapshot 不授予 engine 控制权。 |
| Codec/adapter、transport factory/listener/connection、resolver、interceptor、auth、exception mapping、retry SPI | 可由外部实现的扩展契约 | 由各 SPI XML 文档定义 caller/framework ownership；不暴露 Session 或状态容器。 |
| `SharpLinkRuntimeContext` / Builder | 独立 codec/协议工具可实际使用的 public service container | 业务应用优先 Client/Server Builder；独立创建者负责 Dispose。无 Default、Bind 或公开 manifest mutator；传入 TimeProvider 不转移所有权。 |
| `IRpcChannel`、client-stream sink、`IRpcStub`、`IRpcGeneratedServerBridge`、generated codec factory/descriptor/manifest、contract codec provider resolver | API 4 generated infrastructure | 跨用户生成程序集必须 public；依赖 Abstractions 的窄接口，不依赖 concrete Runtime Context 或内部 engine。只能在注册/启动校验版本，不能每 RPC 查询 Catalog。 |
| `SharpLinkGeneratedAssemblyCatalog` | generated bootstrap infrastructure | `EditorBrowsable(Never)` 与 XML 注明用途；weak catalog 不拥有应用 ALC。动态注册使用 owner 的 assembly registry。 |
| Protocol records、frame codec、buffer pool | 协议工具与有界 codec SPI 支持 | 数据和编码工具不授予 live Session mutator；调用方遵守 buffer 租借/归还约定。 |
| Session、StreamManager、raw dispatcher、Default Context、旧 ABI constructor/adapter | 内部机制或已删除 | 不作为第三方扩展 SPI；不保留 forwarding shim。 |

全部 public/protected 成员（包括 SDK type forwards）在
[`eng/public-api/2.0.0`](../../eng/public-api/2.0.0) 固定；
[`1.1.1 diff`](../../eng/public-api/1.1.1-to-2.0.0.diff) 来自实际已发布 NuGet 包，下载摘要记录在
[`provenance.json`](../../eng/public-api/1.1.1/provenance.json)。上述分类覆盖业务、配置/诊断、可实现 SPI
与 generated/protocol infrastructure，后者公开不代表可直接控制 Runtime engine。

`AnonymousPipeOffer.CreateLocalClientTransportFactory` 属于 transport 的安全所有权入口：
同进程双方共享 SafePipeHandle 对象，跨进程入口继续使用继承句柄；一次性 offer 的两种消费
方式互斥，复制 record 不复制连接许可。这是首个 2.0 public snapshot 的补充，不改变 wire/ABI 版本。

SharedMemory 暂留 Runtime。当前实现使用 BCL memory mapping/pipes 和平台调用，没有独立外部
NuGet 依赖可通过拆包消除；拆分会改变 transport construction/平台测试与包图。没有量化的
NativeAOT rooting/体积收益，因此不声称拆分有 AOT 收益，也不扩大本轮范围。
SharedMemory 的平台及实验性限制继续由 [transports](../transports.md) 约束。

Telemetry 保持各 owner 采集、Runtime 共享机制的现状。Activity/Meter 是 BCL API；Runtime 的
Logging.Abstractions 引用也被非 telemetry 的生命周期日志使用，拆出 Telemetry 不会直接移除它。
本轮不新增 telemetry NuGet 包；若后续有可测的依赖或 AOT 收益，再独立 ADR。
独立算法包 `SharpLink.Compression.Zstd` 保持外部依赖隔离，Core 只含算法无关 SPI/策略。

## Validation and consequences

Release Gate 从实际八个 nupkg 提取 net10.0 assembly，生成完整 API 并与 reviewed snapshot 比较。
改变签名、删除成员或新增 public surface 必须显式更新并 review snapshot；API 的无害编译器
state-machine attribute 不参与比较。版本、程序集/package identity 由独立 package/version gate 检查。
2.0 首发不要求 1.1.1 的 binary compatibility；未来 2.x 使用 2.0.0 package-validation baseline。
2.0 snapshot 是首发 gate，不能用未发布的 2.0 包恢复作为首发前置条件。

`verify-runtime-architecture.sh` 检查已退休的 Default/Bind/engine/adapter pattern，并固定剩余
Task.Yield 和 UTC site 的位置、数量和理由。它不是并发正确性的证明：rollback/counter winner、
drain、ALC、fake-time、Streaming、Chaos 仍由对应测试与发布验证覆盖。

代价是 Runtime 仍暴露独立 context 与协议工具，基础设施 API 仍需 major/ABI 管理；我们接受这项
成本，以保留真实可实现用例并避免新 wrapper/interface 层。迁移条目见 [migration](../migration.md)。
