# SharpLink 0.8.13 深度审核

English: [`en/audit-0.8.13.md`](en/audit-0.8.13.md)

以 0.8.12 commit `db20b9e` 为基线，本批确认五项 P2 以上共享内存生命周期问题：控制通道 Dispose 在初始超时后不再等待 writer；取消 token 本身不能唤醒控制等待；被拒绝的第二次 PipeReader 读取会替换首次读取的取消注册；同一拒绝路径还会清除首次读取的对端通知状态，使数据到达后仍永久等待；PipeWriter 完成会在活跃 spill flush 退出前释放其缓冲区并返回。

最初完整预修复运行中四项最终回归与一个随后撤回的映射假设失败，而 0.8.12 的既有 399 项全部通过；映射假设经所有权复核不够成立，未进入产品修复。替代的通知状态回归随后在未加读取占用保护的候选上单独稳定失败。最终修复让每次可取消控制等待独立持有注册，默认 token 保留无注册快路径；Reader/Writer 删除易被覆盖的共享取消注册，Reader 在修改任何等待状态前原子占有一次读取操作；控制 Dispose 与 spill completion 明确等待后台操作收敛。修复后 Unit 404/404，并通过完整构建、测试、性能与包烟测门禁。

迁移见 [`migration-0.8.13.md`](migration-0.8.13.md)，性能见 [`performance-0.8.13.md`](performance-0.8.13.md)。
