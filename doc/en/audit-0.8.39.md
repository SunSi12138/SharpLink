# SharpLink 0.8.39 deep audit

Using exact 0.8.38 commit `d863dc3` as the baseline, this batch confirmed five P2 improvements: Server terminal failures were invisible to interceptors before unwind; response-bearing Server interceptors could omit their continuation and emit an empty success; wrong Client short-circuit types published contradictory success; framework client-stream enumeration captured caller synchronization contexts; and generated/empty request wire failures were misclassified as unstructured `InvalidDataException` or `Internal`.

Pre-fix, all 117 existing Generator tests passed while only the new generated-wire proof failed; Unit failed only the new empty-request proof; and all nine existing interceptor tests passed while exactly four new context, continuation, result-type, and synchronization-context witnesses failed. The repairs record terminal failure before unwind, require continuations only for response-bearing Server calls, validate every Client result within the tracked pipeline, configure framework stream enumeration not to capture a context, and throw structured `DataLoss` at generated request trust boundaries. Application `InvalidDataException` remains `Internal`.

Final Generator is 118/118, Unit 484/484, Integration 246/246, and non-incremental Release builds with zero warnings/errors. Additional pseudo-mutation controls cover both invalid and valid streaming/OneWay short-circuit shapes. A real TCP interceptor harness changed its median-of-process medians from 41.267 to 40.831 microseconds (-1.06%) with unchanged approximately 1,584.02-1,584.05 B/op.

A 120-second shared-memory Chaos run completed 837,357 successes, 330,087 expected failures, zero unexpected failures, and 23 restarts with zero Client/Server Errors, 218 ms maximum recovery, and all five final metrics at zero. NativeAOT TCP, seven-package pre-commit pack, and fresh-cache package TCP/shared-memory smoke passed. This round found improvements, so the clean-round counter remains 0/3.
