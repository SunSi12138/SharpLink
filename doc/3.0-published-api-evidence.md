# 实际发布版 2.0.3 → 3.0 候选 API 证据（#805 部分交付）

状态：已完成可重跑的**实包差异提取**，不代表 breaking change 已逐项批准，不能据此关闭 #805。

## 复跑

先在干净候选提交上生成九个包（含新增的 `SharpLink.GenerationControl`）。打包必须包含 build，避免新 nuspec 搭配旧 DLL：

```bash
dotnet pack Sharplink.slnx -c Release -o artifacts/nuget -v minimal
dotnet build eng/SharpLink.PublicApi/SharpLink.PublicApi.csproj -c Release -v minimal
python3 eng/compare-published-api.py artifacts/nuget \
  --current-commit "$(git rev-parse HEAD)" \
  --output artifacts/public-api/published-2.0.3
```

`--version` 默认读取 `Directory.Build.props` 的 `VersionPrefix`；预发布包需显式传入完整版本。
输出目录必须不存在；再次运行应选择新目录，以免旧报告或审核基线被覆盖。
已发布库存固定为八包，候选库存与 `verify-public-api.py` 保持一致，目前为九包。
脚本每次从 NuGet 官方 `https://api.nuget.org/v3-flatcontainer` 下载八个 **2.0.3** 包，
不接受源码重建包替代已发布输入。网络/缺包/ZIP 结构/nuspec 身份/候选来源 SHA/
程序集版本或候选 DLL 构建 SHA 不一致均失败；只有全部完成才发布报告目录。

输出包含：

- `provenance.json`：两端包集合及 added/removed package 分类；每个包的来源、版本、包 SHA-256、nuspec repository commit，DLL 路径/SHA-256、程序集身份/MVID/InformationalVersion，以及两类库存的哈希。
- `published/`、`candidate/`：分别保留八个已发布和九个候选程序集的 public/protected API、实际 ExportedType forwarder 和程序集身份。
- `diffs/`：每程序集的 API/forwarder 两类 unified diff，当前共 18 份；没有变化的 diff 为空文件。新增包以 `/dev/null` 为差异起点，保留完整候选 API/forwarder，不伪造旧库存。
- `README.md`：逐程序集差异行数索引。行数不是 API 符号数量，也不是语义兼容性判断。

3.0 允许有意 breaking change，差异本身不会使该脚本失败。
它不会读取或改写 `eng/public-api/3.0.0`；原 `verify-public-api.sh` 的 reviewed baseline 门禁保持独立。
Release Gate 的 pack 作业执行比较，并上传 `published-api-comparison` artifact（保留 30 天）。
PR Fast 执行该脚本的离线错误情形测试。
